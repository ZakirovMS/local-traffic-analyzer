# ПРАВИЛА РАБОТЫ ДЛЯ КОМАНДЫ

**Важно:** Мы работаем через форки. Создайте форк основного репозитория, ведите разработку в нем, а затем отправляйте Pull Request в основной репозиторий.

## Правила написания коммитов

Используем стандарт **Conventional Commits**.

**Формат:** `type(pkg): what was done` (с маленькой буквы, без точки в конце)

**Основные типы:**
* `feat:` — добавили новую фичу
* `fix:` — исправили баг
* `docs:` — поправили документацию
* `test:` — добавили или поправили тесты
* `chore:` — рутина, обновление зависимостей, настройка CI
* `refactor:` — переписали код, но логика не поменялась
* `build:` — изменения в системе сборки или зависимостях (Dockerfile, go.mod)
* `ci:` — изменения в конфигурации CI/CD (файлы workflow)
* `perf:` — изменения для улучшения производительности
* `style:` — исправление форматирования, пробелов и отступов
* `revert:` — откат предыдущего коммита

**В скобках:** указываем пакет, в котором были проведены изменения. Если изменения были в корне -
использовать ключевое слово `root`.

Примеры:
- `docs(frontend): change the description of the project structure`
- `build(root): add new dependence in go.mod`
- `feat(cmd/lta-analyzer): realisation of main logic`
