# Backend: Local Traffic Analyzer

Стек: **Go**.

## Установить перед запуском

- **Go** (версия 1.27.3 или выше)
  Проверка версии: `go version`.

## Структура проекта (Микросервисы)
Каждый сервис — это отдельная папка с `main.go`:
* `lta-analyzer` — анализ трафика
* `lta-api` — общение с React-фронтендом
* `lta-capture` — захват пакетов
* `lta-launcher` — сервис запуска/оркестрации

## Как запустить локально
1. Скачайте зависимости:
   ```bash
   go mod download
   ```
2. Запустите нужный микросервис. Например, API:
   ```bash
   go run ./cmd/lta-api
   ```
   *(Если сервис требует переменных окружения, создайте файл `.env` в корне).*

## Тестирование
Мы пишем тесты в тех же папках, где лежит код, с суффиксом `_test.go` (например, `cmd/lta-analyzer/main_test.go`).

Запустить все тесты во всех сервисах:
```bash
go test -v ./...
```
*Флаг `-v` показывает подробный вывод каждого теста.*

Запустить тесты с проверкой на Data Race:
```bash
go test -race ./...
```

## Линтинг
Используем стандартный линтер `golangci-lint`.
Установка:
```bash
go install github.com/golangci/golangci-lint/cmd/golangci-lint@latest
```
Запуск:
```bash
golangci-lint run
```

## Как работает CI
Когда вы создаете Pull Request, меняющий файлы в папке `cmd/` (или `go.mod`), автоматически запускается workflow **CI for Go (Backend)**. Он делает две вещи параллельно:
1. **Go Lint** — запускает `golangci-lint run`
2. **Go Test** — запускает `go test -race ./...`.
